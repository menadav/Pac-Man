# Pac-Man

## Description

A modern Python remake of the classic arcade game **Pac-Man**, built with
`pygame` and an object-oriented architecture. The player navigates a maze
generated by an external _A-Maze-ing_ package, eats pacgums and super-pacgums,
avoids four ghosts (Blinky, Pinky, Inky, Clyde), and tries to reach the highest
possible score across multiple levels.

The game features:

- A JSON configuration file (with `#` line comments) describing levels and
  scoring rules.
- A persistent top-10 highscore system.
- A main menu, an instructions screen, a highscores screen, a pause menu and a
  game-over / victory screen.
- A cheat mode dedicated to peer review.
- Robust error handling: invalid config values are clamped to safe defaults
  and a clear message is logged instead of crashing.

## Instructions

### Install

```sh
make install
```

This installs `pygame`, `pydantic`, the development tools (`flake8`, `mypy`)
and the local _A-Maze-ing_ package located in
`src/map/mazegenerator-00001-py3-none-any/`.

### Run

```sh
make run                  # uses config.json by default
make run CONFIG=foo.json  # use a custom config file
```

Or directly:

```sh
python3 pac_man.py config.json
```

## Configuration

The config file is JSON with `#` line comments. Lines starting with `#` are
stripped before parsing.

```json
{
    "highscore_filename": "highscores.json",
    "seed": 42,
    "lives": 3,
    "points_per_pacgum": 10,
    "points_per_super_pacgum": 50,
    "points_per_ghost": 200,
    "levels": [
        {"level_id": 1, "width": 20, "height": 20,
         "pacgum": 40, "level_max_time": 90}
    ]
}
```

### Keys

| Key                       | Type          | Default            | Notes                                                     |
| ------------------------- | ------------- | ------------------ | --------------------------------------------------------- |
| `highscore_filename`      | string        | `highscores.json`  | Path where the top-10 highscores are persisted.           |
| `seed`                    | int >= 0      | `42`               | Seed of the first level (other levels are random).        |
| `lives`                   | int >= 1      | `3`                | Initial number of lives.                                  |
| `points_per_pacgum`       | int >= 0      | `10`               | Score gained per pacgum eaten.                            |
| `points_per_super_pacgum` | int >= 0      | `50`               | Score gained per super-pacgum eaten.                      |
| `points_per_ghost`        | int >= 0      | `200`              | Score gained per ghost eaten while in escape mode.        |
| `levels`                  | array         | required           | Ordered list of `LevelConfig` objects (see below).        |

### LevelConfig

| Key              | Type           | Default | Notes                                                   |
| ---------------- | -------------- | ------- | ------------------------------------------------------- |
| `level_id`       | int            | `1`     | Auto-renumbered if duplicated.                          |
| `width`          | int [8, 40]    | `20`    | Clamped: the maze generator is recursive.               |
| `height`         | int [8, 40]    | `20`    | Clamped: the maze generator is recursive.               |
| `pacgum`         | int >= 1       | `42`    | Number of pacgums spawned in corridors.                 |
| `level_max_time` | int >= 1 (sec) | `90`    | Time limit; the game ends when it reaches zero.         |

### Faulty config handling

- Missing keys are filled with the defaults listed above.
- Invalid values are clamped (or replaced with the default) and a
  `[CONFIG WARNING]` line is printed.
- Unknown keys are ignored.
- The program never crashes with a Python traceback: all parsing errors are
  reported with a clear `[ERROR] ...` message.

## Highscore system

Highscores are persisted as a JSON array in the file referenced by
`highscore_filename`. Each entry has the shape `{"name": str, "score": int}`.

- The file is loaded at game start and rewritten at game end.
- Player names are limited to **10 characters**, alphanumeric and spaces only.
- Scores must be non-negative integers.
- Only the **top 10** entries are kept.
- Any read/write/format error is silently swallowed and replaced by an empty
  list, so a corrupted file never crashes the game.

This format was chosen because it is human-readable, trivial to inspect, and
plays well with the `pydantic` models that already validate the rest of the
configuration.

## Maze generation

The maze is built by the externally-provided `mazegenerator` package
(_A-Maze-ing_). The wrapper used here is:

```python
self.maze_engine = MazeGenerator(
    size=(width, height),
    seed=<seed>,        # first level uses ParseConfig.seed; later levels random
    perfect=False,      # required by the Pac-Man subject
)
```

We use the package **as-is**, without modifying it. Its output is a 2-D matrix
where each cell encodes its four walls as bit flags (`1=N`, `2=E`, `4=S`,
`8=W`). On top of these flags we OR-in `16` for a pacgum and `32` for a
super-pacgum (see `src/entities/items.py`).

`width` and `height` are clamped to `[8, 40]` to stay safely below Python's
default recursion limit.

## Implementation

### General software architecture

```
pac_man.py
└── GameMannager (src/engine/dataprocess.py)
    ├── Menu              (src/engine/loop/loop_menu.py)
    ├── HighScoreScene    (src/engine/loop/loop_highscore.py)
    ├── Instructions      (src/engine/loop/loop_instructions.py)
    ├── GameRun           (src/engine/loop/loop_game.py)
    │   └── EntitiesMannager (src/entities/entitiesmannager.py)
    │       ├── Items     (super-pacgums, pacgums, respawn point)
    │       ├── Player    (src/entities/player.py)
    │       └── GhostMannager (src/entities/ghost_model/ghostmannager.py)
    │           ├── Blinky / Pinky / Inky / Clyde (each with its own AI target)
    │           └── Ghost (shared movement + decision logic)
    └── GameOver          (src/engine/loop/loop_end.py)
```

- Every screen inherits from `BaseScene` (`src/engine/scene.py`) and exposes
  `handle_events` and `draw`. Scenes communicate with `GameMannager` through a
  `(signal, value)` tuple (e.g. `("GAME", 0)`, `("END", 12500)`).
- The `EntitiesMannager` is the **single source of truth** for the on-screen
  tile size and the maze centering offsets. It reserves a horizontal strip at
  the top of the screen for the HUD and centers the maze in the remaining
  area. The tile size is snapped to a multiple of 6 so that the integer pixel
  steps used by Pac-Man (3 px/frame) and the ghosts (1 or 2 px/frame) always
  land exactly on tile centers.
- Configuration is parsed by `pydantic` models in `src/parse/models.py`,
  giving us automatic validation, clamping and clear error messages.

### In-game HUD

Always visible during gameplay: current score, current level, remaining time
for the level, and remaining lives (rendered as small Pac-Man icons). A
`CHEAT MODE` indicator appears as soon as the cheat mode is activated.

### Cheat mode

Toggled from the pause menu (ESC → CHEAT → ENTER). When active:

- Pac-Man is invincible.
- Pac-Man moves at double speed.
- `SPACE` skips the level, `+/-` adjusts the life count.
